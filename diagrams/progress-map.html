工程护栏（今天实战踩出来的）

R-18 / R-19 编码健壮性

中文输出在 cp1252/cp437 重定向下必崩（`--help` 都跑不了）→ main() 最前 reconfigure UTF-8，独立脚本同样自带兜底。

R-20 / R-21 升版守卫

契约与 schema 升版必须同批同步台架；CONTRACT_VERSION 故意写死（逼同步），schema_version 跟常量走。

R-22 端口与 G7

PG 默认 55440（禁 55432–55434）；G7 只在提供覆盖率报告时启用，无报告不得判红。

R-24 容器命名

compose 禁用固定 container_name：多工作树/多 clone/台架互撞（实测撞过）。

R-25 / R-26 环境与资源

显式 --db 优先于环境变量；config/models.yaml 必须能在任意 cwd 定位。

R-27 / R-28 对拍与回灌

A12 探针必须做驱动归一（PG 元组 vs SQLite 标量）；回灌区只取「本轮 + 上一轮」，否则 package_hash 随库历史漂移。

R-29 / R-30 分支与交接

已 squash 合并的分支禁止续推（原提交不进 main）；实现方的覆盖桩落 benchmarks/**、由验证方改写进 tests/** 才计入覆盖。

R-31 / R-32 退出码与门槛口径

rc 三分：未知值 2（argparse 原生，不劫持）· 合法但缺依赖/凭据 4 · I/O 与 DB 5；覆盖率门槛只算纯逻辑白名单（D4 §3.5），store/postgres.py 排除、只作 A20b 报告项。

子进程覆盖盲区

台架走 subprocess 跑 CLI 时子进程覆盖不计入父进程 --cov（cli.py 曾长期显示 0%）→ 覆盖率用例必须 in-process 调 cli.main()。

合并顺序

PR 基点落后于最新 main 时，squash 合并会在 main 上产生「新实现 + 旧期望」的假绿真红（P2 #49 撞过一次）→ 合前先 rebase，合后跑全量台架。
