# KFPA v2 设计规格（补充件）

> 定位：日式详细设计方式的 AI 化。人出原始详细设计，主BOT（旗舰模型）辅助设计并转译为任务包，Flash（低思考模型）零思考执行。失败的经济成本 = token，靠快速试错而非一次做对。

## 1. 角色与职责

| 角色 | 职责 | 明确不做的事 |
|---|---|---|
| 人类设计者 | 原始详细设计、设计变更、質問票批量确认、每周批量承认小变更 | 不写代码、不逐条实时响应 |
| 主BOT（旗舰） | ① 设计辅助（起草草案/質問票/对抗评审）② 设计转译（任务包）③ 调度与异常（分级重试/影响分析/重规划）④ 反馈回灌 | 不擅自改人的设计决策 |
| 功能BOT（旗舰/中档） | 设计功能N + 审核第 N-1 轮提交的代码 | — |
| Flash 执行器 | 纯编码、快速修复、局部优化 | 不写测试、不做设计决策 |
| 质量层 | 集成/回归/安全测试、审查聚合、三态门禁 | 测试从设计规约生成，与实现解耦 |

## 2. 轮次生命周期

1. 人提交原始设计（或设计变更）
2. 主BOT 转译 → 产出**質問票清单**（歧义报告）上呈人
3. 人确认后放行 → 主BOT 生成编码任务包
4. 功能N BOT：设计功能N + 审核第 N-1 轮代码（返工上限 = 一轮）
5. Flash 编码
6. 质量门禁三态判定
7. 出口处理（见 §5）
8. 执行结果 → 项目记忆 + 沉淀闸门

## 3. 编码任务包强制结构

- 目标描述（做什么，一句话）
- 验收标准（可测试的断言，逐条列出）
- 边界条件清单（输入域、异常流、并发/幂等要求）
- 接口契约（签名、入参出参、错误码）
- 禁止事项（不许动的模块、不许引入的依赖、不许的模式）
- 回灌区（上一轮失败原因与规避要求，若有的话）

> 任务包是全系统最贵的资产：Flash 越笨，规约必须越精确。含糊的任务包会被高速执行成确定性的错误。

## 4. 質問票（歧义报告）机制

- 生成时机：主BOT 转译设计时，凡遇到无法唯一确定解释的表述即开票
- 每张票：票号 / 位置（设计书章节）/ 两种可能解释 / 主BOT 倾向 / 影响面
- 处理：攒批处理（不逐条实时），确认结果写入项目记忆的質問票台账
- 硬规则：存在未关闭的高影响質問票时，不得生成任务包

## 5. 分级重试与三态出口

| 门禁结果 | 处理 | 是否惊动人 |
|---|---|---|
| 通过 | 提交版本管理（按轮快照） | 否 |
| 需修复 | Flash 自主重试，**失败原因必须回灌新任务包**；同类失败 ≥2 次自动升级 | 否（升级时是） |
| 阻塞 | 升级主BOT → 变更影响分析 → 重规划（改需求/改任务） | 是 |

- 重试 ≠ 掷骰子：失败反馈不回灌，重试无意义
- 每轮快照绑定（代码+任务包+测试结果），回滚一键完成

## 6. 维护轻量通道（快车道）

- 判据（主BOT 影响分析自动给出）：不新增/不修改接口契约、不改数据模型、波及面 ≤ 1 个模块
- 流程：小变更 → 主BOT 微型规格 → 人**每周攒批**承认 → Flash 直跑
- 触碰设计边界的变更一律升级回完整设计回合

## 7. 知识沉淀闸门（防知识库中毒）

- 沉淀候选先过：置信度门槛 + 人工抽检（抽样率可随该来源历史准确率动态调整）
- 新知识先进待验证隔离区，被 ≥1 个后续轮次成功复用后才转正
- 失败记录单独沉淀为回避模式清单，下一轮任务包显式规避——负知识同样值钱
- 不合格沉淀直接丢弃，不进知识库

## 8. 适用域与免责声明

- 适合：需求稳定、规格明确的企业系统 / CRUD 密集型 / 迁移重构 / 维护保守
- 不适合：需求边做边长的探索型产品（详细设计个寂寞）
- 两种用法同一套基础设施：懒人模式（全自动，AI 连设计一起包，错误成本=token，上限由门禁与知识库质量决定）；正经模式（human 详细设计全流程纪律）
